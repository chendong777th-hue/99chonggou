## 3. 架构宗旨和不可破坏的不变量

### 3.1 单 Message Writer

历史、实时、发送、撤回、删除必须经过同一个 `MessageReconciliationWriter` 裁决边界。

当前实现核心：

- `third_party/tencent_cloud_chat_uikit/lib/business_logic/view_models/message_reconciliation_writer.dart`
- `third_party/tencent_cloud_chat_uikit/lib/business_logic/view_models/tui_chat_global_model.dart`
- `commitMessageDelta(...)`
- `setMessageList(...)` 只能作为 Writer 后面的兼容投影发布器，不能重新成为独立事实源。

当前 `_messageListMap` 直接赋值审计结果：

- `tui_chat_global_model.dart` 中两处 `_messageListMap[storageKey] = sorted` 位于 `setMessageList` 内，属于投影边界。
- 发送认领、行替换、编辑、撤回、删除等正式变更已经通过 `commitMessageDelta -> MessageReconciliationWriter.applyDelta -> setMessageList`。
- `_messageListMap.remove/clear` 仍需在 IM-10/IM-11 按清账号、清会话、窗口投影逐条登记，不能只凭“不是赋值”视为安全。

### 3.2 必须保留的 IM-04 修复

严禁丢失 `tui_chat_global_model.dart` 中以下修复：

```dart
final resolvedStableIdentity = readOutgoingStableId(expected) ??
    stableIdentity;
```

它位于行替换 Writer delta 附近，并用于 `row_replace` 的稳定身份和 `outgoingStableID`。不要改回只使用 `stableIdentity`。

### 3.3 账号、会话和 generation

所有长异步链必须携带或校验：

- `ownerUserId`
- canonical conversation scope
- `accountGeneration`
- `domainGeneration`
- `eventNamespace`
- Writer Lease `fencingToken`

群 Provider Seq、账号入口序号、scope 入口序号用途不同，不能混用。单聊不得使用群 Seq 连续性推理。

### 3.4 `OutcomeUnknown`

只要不能证明 SDK 未发送，就不得自动重发。超时、连接中断、进程杀死后存在调用可能性的操作必须保持 `OutcomeUnknown`，等待历史/实时/查询认领或用户明确处理。

6. Future 超时、异常中断、回执乱序或先于 Future 时进入 `OutcomeUnknown`，不得自动补发。

10. 保护现有图片/视频字节、质量、尺寸、上传协议和 UI 体验，不以重构名义降级。

没有 ADR 不得自行猜测并实施双写。可以先补契约、Adapter 和失败回滚，但不能把产品语义标记为完成。

### 8.3 IM-09 退出门禁

- 旧 SDK 会话快照不能复活已清未读。
- 已读水位只单调前进。
- SDK 已读上报只是副作用，不能反向覆盖本地更高水位。
- 最后一条消息、未读、撤回最后一条消息和草稿一致。
- 置顶/免打扰失败正确回滚。
- 每个字段只有一个正式写入者。
- 切账号和多设备事件带 owner/generation，不串线。
