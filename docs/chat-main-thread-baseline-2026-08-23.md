# 聊天页 Profile 基线（2026-08-23）

- 基线提交：`363b315`（代码基线 `6333e34`）
- 设备：iPhone 16（无线），iOS 26.2，Flutter Profile
- 场景：多个群聊开关、360 条长历史窗口、键盘开关、连续文字发送、
  图片密集群、7–9 张图片批量选择和发送

## 结果

- `set_message_list_ms`：20–120 条通常 0.1–3.2ms；连续扩到 360 条时
  最高 9.8ms。媒体连续回执期间出现多次 0.6–4.3ms 整表整理。
- `image_decode_ms`（打开预取入口）：21–25 条约 0.002–0.115ms。
- `keyboard_layout_ms`：约 0.002–0.007ms，不是当前主压力。
- `group_metadata_apply_ms`：本地首屏快照约 0ms，不是当前主压力；
  但多来源竞争仍按 055 做正确性收敛。
- 媒体现有诊断：文件解析首项约 67–80ms，后续常见 31–36ms；
  期间记录到 40–60ms 慢帧，批量发送回执又触发多次消息整表整理。

## 决策

数据支持执行 053：长窗口和连续媒体回执会重复支付整表整理成本。
数据支持执行 054：文件解析明显超过单帧预算。055 以消除群资料多来源竞争为
主目标，不把近 0ms 的本地 apply 当成计算热点。键盘路径保持现状。

本次命令行 Profile 没有导出 Instruments `.trace`，因此最终全链路验收仍需补一轮
Time Profiler/Core Animation 对照；本轮算法范围只采用已有日志明确点名的边界。
